## Agent Brief

**Category:** enhancement
**Summary:** Key every `.each` test table by a `name` field used in the title, and lint it.

**Current behavior:**
`AGENTS.md` (Testing Pattern) says every test case has a descriptive `name`, used as the `'$name'` title. Older tables break it in two ways: rows keyed `label` with `'$label'` titles, and rows with no name at all whose titles print `$input` and `$expected`. Nothing checks the rule, so the review must catch every new table that breaks it.

**Desired behavior:**
- Every object row of an `it.each` / `test.each` / `describe.each` table has `name: string` as its first field, and its row type says so.
- Every `.each` title contains `$name`. It may show other fields beside it (`'$name: "$input" -> "$expected"'`), which keeps the input tables' titles as informative as today.
- For the `label` tables, rename only the row key that feeds the title. A row whose data has its own `label` field (the sort-by-label and list-to-record tests) keeps that field.
- In the input tables, each `name` describes the case (`'an acronym prefix gets one underscore per capital'`), not a copy of the input.
- The two `'returns a string'` tests of the `TO_LOCAL_NUMBER_WITH_1_F_DIGIT` and `TO_LOCAL_NUMBER_WITH_2_F_DIGITS` suites go: their tables' `toBe` rows already pin the string.
- A new `testRestrictedSyntax` entry in `eslint.config.mjs` flags an `.each` title literal that lacks `$name`, beside the existing `%s` entry, with a message in the same style (it says how to fix).

**Key interfaces:**
- The row types of the test tables: `Array<{ name: string, ... }>`.
- `testRestrictedSyntax` in `eslint.config.mjs`: one more `{ selector, message }` entry. A starting point to verify, not a given: `CallExpression[callee.callee.property.name="each"] > Literal.arguments:not([value=/\$name/])`.

**Acceptance criteria:**
- [ ] A grep of `tests/` for `'$label` and for a `label: string` row key that feeds a title finds nothing.
- [ ] `bun run lint` passes with the new entry, and a scratch test file whose `.each` title lacks `$name` gets the new message (checked once, then deleted).
- [ ] The label files' test titles keep their text: compare `bun test` output before and after for those files.
- [ ] The test count drops only by the 2 removed `'returns a string'` tests; `bun run check` passes.
- [ ] One commit per `tests/` category folder, `test:` type; the lint entry lands in the last commit, once every table passes it.
- [ ] On resolving, the pointer in `AGENTS.md` (Testing Pattern) that names this ticket as the list of old tables is removed, since none remain.

**Out of scope:**
- Tuple-row tables (`[input, expected]` arrays) beyond what the new lint entry flags; if it flags some, convert them to object rows with a `name`.
- Any change to the tested utilities, or to assertions other than the 2 removed `'returns a string'` tests.
- Other lint rules or the rest of `eslint.config.mjs`.
